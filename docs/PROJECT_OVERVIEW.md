# RentEase project overview

RentEase is a self-contained frontend demonstration of rental property discovery and management for Bangladesh. It preserves the adapted Horizon Estate visual foundation and implements public rental pages plus tenant, landlord, and administrator workflows. Sample listings use Dhaka, Chattogram, and Sylhet locations and BDT amounts.

## Technologies

- Next.js 16 App Router and React 19
- JavaScript with JSX
- Tailwind CSS 4
- Lucide React icons
- Browser local storage and React client state for demo data

## Data persistence

`src/data/rentease.js` defines the seed data and demo credentials. `src/lib/demo-store.js` is the centralized browser storage boundary. It reads, initializes, migrates, updates, and resets the stored data; components subscribe to its same-tab custom events, and browser `storage` events refresh open tabs.

The single `rentease-demo-data` JSON record contains users, properties, applications, rental agreements, rent and utility payments, maintenance requests, and notifications. Dashboard actions update shared records, so an application, a landlord decision, a payment, or a maintenance status change is visible to the related roles. New IDs are generated by the store helper. Missing data initializes from the seed; malformed or unsupported data logs an error and restores the seed. A missing notifications array in an older supported record is migrated to an empty array without discarding other records.

`rentease-demo-session` stores only the current user ID: local storage when “Remember me” is selected and session storage otherwise. User profile details are resolved from the shared user collection. Reset is available from the dashboard profile menu, asks for confirmation, restores seed records, and signs the user out.

This design is for a university demo only. Browser storage is editable, can be cleared, and is not shared across browsers or devices. Demo account passwords are illustrative sample values; authentication and role checks in client code are not production security. No real payment, email, chat, identity verification, or tenancy service is connected. Do not enter real passwords, payment credentials, or sensitive personal information.

## Architecture and visual constraints

The public pages use the existing Header, Footer, HeroSection, PropertyCard, and original global CSS/Tailwind language. Dashboard components use the same neutral palette, type, button, card, and spacing patterns. Tenant, landlord, and admin layouts all reuse `DashboardApp`, which renders role-specific content without adding a separate design system.
